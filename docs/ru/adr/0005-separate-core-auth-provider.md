# ADR-0005: Размещать провайдер аутентификации вне classloader плагина

- Статус: принято
- Дата: 2026-07-18

## Контекст

Плагины Openfire используют изолированный classloader и могут загружаться или выгружаться во время работы сервера. Настроенный `AuthProvider` создаётся ядром Openfire и должен быть доступен в течение всего жизненного цикла сервера.

Официальное руководство Openfire по собственным провайдерам аутентификации рекомендует размещать JAR провайдера в каталоге `lib`, а не поставлять его только внутри плагина.

## Решение

Проект выпускает два артефакта:

1. `mobileaccess.jar` — плагин Openfire для администрирования, проверки пользователя и группы, управления учётными данными и аудита.
2. `mobileaccess-auth-provider.jar` — библиотека для classpath ядра, устанавливаемая в каталог `lib` Openfire и подключаемая через `HybridAuthProvider`.

Провайдер является только проверяющим компонентом:

- пароли нельзя получить в открытом виде;
- метод `setPassword` через API аутентификации не используется;
- создание, замена и отзыв учётных данных выполняются административным плагином;
- провайдер только проверяет переданное имя пользователя и пароль.

## Последствия

- После установки или обновления JAR провайдера требуется перезапуск Openfire.
- Выгрузка административного плагина не удалит класс настроенного провайдера аутентификации.
- Плагин и провайдер взаимодействуют через стабильную схему базы данных, а не через прямые ссылки на Java-объекты.
- Релиз должен содержать оба артефакта и инструкции по их установке.
